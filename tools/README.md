# Excel join 表制作与 YAML 生成指南

本目录的 `xlsx_to_yaml.py` 用于把快思聪设备 join 表转换成 Home Assistant
可加载的 `crestron.yaml`。转换器只读取标准 `.xlsx` 文件，不支持旧版 `.xls`
或 CSV。

脚本只使用 Python 标准库，不需要安装 `openpyxl`、`pandas` 或 PyYAML。

## 1. 创建工作簿

最简单的方法是复制仓库根目录的 `sample.xlsx` 作为模板，再按项目修改。
也可以在 Excel、WPS 或 LibreOffice 中新建工作簿。

工作簿可以包含以下四个设备 sheet：

- `灯光`
- `插座`
- `窗帘`
- `空调`

sheet 名必须与上面完全一致。可以保留 `说明` sheet，转换器会将它作为说明页正常
忽略；其他未知 sheet 会产生警告。

每个设备 sheet 的第一行必须是表头：

- 不要在表头上方增加标题行。
- 不要合并表头单元格。
- 表头文字必须与本文一致，不能自行改名。
- 列的顺序可以调整，转换器按表头名称读取。
- 未使用的单元格保持空白即可。

## 2. join 填写规则

所有 join 单元格只填写十进制数字，例如 `701`：

- 数字 join：`1`–`4096`
- 模拟 join：`1`–`1024`
- 不要填写 `d701`、`a480`、`1.0`、`+1` 等格式。
- 建议直接填写静态数字，不要使用公式。

“亮度、色温、位置、温度、室温”等列填写的是模拟 **join 编号**，不是亮度、
色温、位置或温度的当前值。

`序号` 仅供人查看，转换器不会读取它。

### 控制与反馈约定

- HA 只监听 CP4N 推送，不轮询快思聪。
- 数字量“开/关”Join 既用于发送控制，也由 CP4N回传稳定状态。
- 状态回传中通常只有“开”或“关”一根为高；两根同时高或同时低视为过渡/未同步，
  HA 保留最近状态。
- HA 发出的开、关、停止命令不受当前反馈状态限制。
- 模拟量 Join 同样由 CP4N同步；HA 写入后先显示乐观状态，收到反馈后以反馈为准。

## 3. 灯光 sheet

推荐表头：

| 序号 | 楼层 | 房间 | 名称 | 功能 | 亮度 | 色温 | 开 | 关 |
|---|---|---|---|---|---|---|---|---|

示例：

| 序号 | 楼层 | 房间 | 名称 | 功能 | 亮度 | 色温 | 开 | 关 |
|---|---|---|---|---|---|---|---|---|
| 1 | 1F | 客厅 | 灯带 | 双色温 | 1 | 201 |  |  |
| 2 | 1F | 客厅 | 吊灯 | 单色温 | 2 |  |  |  |
| 3 | 1F | 走廊 | 壁灯 | Relay |  |  | 1 | 2 |

转换规则：

- “亮度”和“色温”都有 join：生成 `type: color_temp` 双色温 `light`。
- 只有“亮度”：生成 `type: brightness` 单色温 `light`。
- 只有完整的“开”和“关”：生成 `type: onoff` 只开关 `light`。
- 亮度运行值为 `0`–`65535`；色温运行值为 `2700`–`6500 K`。
- “亮度/色温”与“开/关”混合填写时，该行会因控制方式不明确而被跳过。
- 只有“色温”、开关不成对或没有任何能力的行会被跳过。
- “功能”列只是备注，不参与类型判断。

## 4. 插座 sheet

推荐表头：

| 序号 | 楼层 | 房间 | 名称 | 开 | 关 |
|---|---|---|---|---|---|

示例：

| 序号 | 楼层 | 房间 | 名称 | 开 | 关 |
|---|---|---|---|---|---|
| 1 | 1F | 客厅 | 落地灯插座 | 147 | 148 |

“开”和“关”都是必填的数字 Join，也承载 CP4N回传状态。缺少任意一个时该行会
被跳过。生成 `switch`，并设置 `device_class: outlet`。

## 5. 窗帘 sheet

推荐表头：

| 序号 | 楼层 | 房间 | 名称 | 类型 | 开 | 关 | 停止 | 位置 |
|---|---|---|---|---|---|---|---|---|

示例：

| 序号 | 楼层 | 房间 | 名称 | 类型 | 开 | 关 | 停止 | 位置 |
|---|---|---|---|---|---|---|---|---|
| 1 | 2F | 女儿房 | 卷1 | shade | 700 | 701 | 702 | 480 |
| 2 | 2F | 女主卧 | 布帘2 | curtain | 704 | 705 | 706 | 481 |
| 3 | 1F | 露台 | 遮阳篷 | awning | 708 | 709 | 710 | 482 |

“开”“关”“停止”都是必填的数字 join；缺少任意一个时，该行会被跳过。“位置”
是可选的模拟 join，运行时值约定为 `0`–`100`：

- `0`：全关
- `100`：全开

CP4N通过现有“开/关”Join 回传打开/关闭状态，不需要额外填写“正在打开”“正在
关闭”等反馈列。无论当前反馈是什么，HA 都允许再次发送开、关、停止命令。填写
“位置”后，HA 提供百分比控制；尚未收到位置反馈时使用乐观值并标记为假定状态。

“类型”支持以下 Home Assistant cover 类型：

| 类型 | 含义 |
|---|---|
| `awning` | 遮阳篷 |
| `blind` | 百叶帘 |
| `curtain` | 布帘、窗帘 |
| `damper` | 风阀、挡板 |
| `door` | 门 |
| `garage` | 车库门 |
| `gate` | 院门、大门 |
| `shade` | 卷帘、遮光帘 |
| `shutter` | 百叶窗、护窗 |
| `window` | 可开关窗户 |

类型忽略英文字母大小写和首尾空格。类型为空或不在支持列表中时，统一生成
`type: curtain`。转换器不会根据“卷1”“布帘2”等名称猜测类型。

## 6. 空调 sheet

推荐表头：

| 序号 | 楼层 | 房间 | 开 | 关 | 制冷 | 制热 | 通风 | 除湿 | 低速 | 中速 | 高速 | 自动 | 温度 | 室温 | 风速值 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|

示例：

| 序号 | 楼层 | 房间 | 开 | 关 | 制冷 | 制热 | 通风 | 除湿 | 低速 | 中速 | 高速 | 自动 | 温度 | 室温 | 风速值 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | 2F | 主卧 | 400 | 401 | 402 | 403 | 405 | 406 | 407 | 408 | 409 | 410 | 400 | 401 | 450 |

转换规则：

- “开”和“关”是必填的数字 join；缺少任意一个时，该行会被跳过。
- “制冷、制热、通风、除湿”是可选的数字 join。
- “低速、中速、高速、自动”是可选的数字 join。
- “温度”和“室温”是可选的模拟 join。
- 温度设定范围为 `16`–`30 °C`。
- “风速值”目前有意忽略：约定值为 `-1/10/50/100`，分别表示自动/低/中/高，
  现阶段使用四根数字量风速 Join。
- 数字量模式和风速 Join 由 HA 控制并由 CP4N回传。
- 每行生成一个 `climate` 实体，名称为“楼层.房间 空调”。

## 7. 名称与重复项

灯光、插座和窗帘的实体名称格式为：

```text
楼层.房间 名称
```

空调名称格式为：

```text
楼层.房间 空调
```

同一平台内出现重复实体名时，转换器会为第二个及后续实体追加 `2`、`3` 等后缀。
“楼层”和“房间”还用于生成分组注释和 `suggested_area`（例如 `B2.会客厅`），不参与
设备类型判断。`suggested_area` 只帮助 HA 为新设备建议区域，不覆盖用户已手工设置
的区域。

## 8. 运行转换器

在仓库根目录执行：

```bash
python3 tools/xlsx_to_yaml.py 你的设备表.xlsx 输出目录
```

脚本会生成：

```text
输出目录/crestron.yaml
```

也可以把第二个参数直接写成完整 YAML 文件路径：

```bash
python3 tools/xlsx_to_yaml.py \
  你的设备表.xlsx \
  custom_components/crestron/crestron.yaml
```

目标文件已经存在时会被覆盖，正式生成前请先备份手工修改过的 YAML。

成功输出示例：

```text
[info] ignored instruction sheet '说明'
[info] 灯光: ignored 1 empty/template row(s): 108 (template row ...)
[info] 灯光: converted 205 entity row(s)
[warning] 灯光!6: duplicate entity name 'B2.车库 吊灯'; renamed to 'B2.车库 吊灯 2'
wrote .../crestron.yaml (light:205, climate:18, cover:32, switch:9; errors:0, warnings:1)
```

这些转换结果、最终数量汇总和“下一步”提示会原样复制到生成 YAML 的头部，并全部
加上 `#`，因此既能保留本次完整命令行输出，又不会参与配置解析。报告包含每个设备
sheet 的实体数；空行/模板行的 Excel 行号及忽略原因；未知 sheet、未知窗帘类型、
重复 Join、重复实体名及自动改名；`风速值` 等明确不采用的非空单元格；以及每一条
校验错误。缺少、未知、空白或重复表头也会逐项报告，避免列名拼错后整列能力静默
消失；缺少必填 Join 表头或表头重复会作为 error。`灯光!108` 表示“灯光 sheet 的
Excel 第 108 行”。

只检查、不生成文件：

```bash
python3 tools/xlsx_to_yaml.py --check 你的设备表.xlsx
```

检查会报告准确的 sheet、Excel 行号和原因。错误包括 Join 格式/范围错误、必填
Join 缺失或灯光控制方式混填；未知窗帘类型、重复 Join、重复实体名会产生警告。
存在错误时，正常生成命令会输出完整错误清单后停止，且不会覆盖已有 YAML；警告
不会阻止生成。

## 9. 在 Home Assistant 中加载

将生成文件放到 Home Assistant 配置目录，并在 `configuration.yaml` 中加入：

```yaml
crestron: !include crestron.yaml
```

然后：

1. 打开生成的 `crestron.yaml`，确认顶部 `port:` 是实际 XSIG 监听端口。
2. 在 Home Assistant 中检查配置。
3. 重启 Home Assistant。

如果文件放在其他目录，`!include` 路径必须相对于 `configuration.yaml`。例如：

```yaml
crestron: !include custom_components/crestron/crestron.yaml
```

## 10. 常见问题

### 某个 sheet 被跳过

检查 sheet 名是否精确写成 `灯光`、`插座`、`窗帘` 或 `空调`。`说明`会正常忽略，
其他未知名称会产生警告。

### 某一行没有生成

检查该设备要求的必填 join 是否完整，并确认单元格只含十进制数字。

### 窗帘全部生成成 curtain

检查窗帘 sheet 的第一行是否真的包含精确表头“类型”，以及类型值是否在支持列表中。
没有“类型”列、单元格为空或值不受支持时，都会按 `curtain` 处理。

### 修改 Excel 后输出没有变化

确认保存的是传给命令的那一份 `.xlsx` 文件，并避免在 Excel 尚未保存时运行转换器。

### HA 报 join 越界

检查数字 join 是否在 `1`–`4096`，模拟 join 是否在 `1`–`1024`。转换器负责读取
表格，Home Assistant 集成会在加载 YAML 时执行最终范围校验。

## 11. 上传组件到测试服务器

`deploy_to_ha.sh` 使用 `scp` 上传本仓库的
`custom_components/crestron` 到远端 `/homeassistant/custom_components/crestron`，
可选择先从 Excel 生成并上传 `local/crestron.yaml`，最后执行
`ha core restart`：

```bash
tools/deploy_to_ha.sh
```

不带参数时会交互式询问服务器地址、用户名、密码、是否生成 YAML 和是否上传
YAML。选择重新生成时，脚本会按文件名顺序使用 `local/` 中找到的第一个
`.xlsx` 作为输入路径默认值；如果目录中没有 `.xlsx`，默认值为空，必须手工
输入。密码留空即使用 SSH key。完整参数见：

```bash
tools/deploy_to_ha.sh --help
```

密码登录依赖 `sshpass`；推荐使用 SSH key。组件目录中已有的 `crestron.yaml`、
`__pycache__` 和 `.pyc` 不会随代码无条件上传，只有确认上传
`local/crestron.yaml` 后才会覆盖远端运行配置。
